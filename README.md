# Runvis — Landing Page

Runvis (런비스) 공식 랜딩/베타모집 페이지. 정적 사이트, 런타임 의존성 0.
루트 5페이지(`index.html` · `run.html` · `how-it-works.html` · `privacy.html` ·
`terms.html`)와 그것을 5개 언어로 프리렌더한 25페이지, 합쳐서 30페이지다.
빌드는 Node 스크립트 두 개(프리렌더 + 드리프트 검사)이고, 에셋을 새로 만들 때만
파이썬 두 개가 더 붙는다.

그 30페이지 밖에 `404.html`이 하나 더 있다. GitHub Pages가 못 찾은 **모든** 경로에
이 파일을 돌려주므로 깊이가 정해져 있지 않고, 그래서 URL이 전부 절대 경로이며
`RunvisBase`가 항상 `"/"`다. 언어별 사본도 hreflang도 sitemap 항목도 없다 —
보낼 `/de/404.html`이 없기 때문이다. 대신 `check-content.mjs`의 `EXTRA` 목록에
들어 있어 2·3·8·21번 검사를 똑같이 받는다.

`how-it-works.html`은 라운드 12에 생겼다. 홈이 1280px 폭에서 16,408px였고
`#beta` 한 섹션이 2,653px였다 — 폼·동의·심박존 계산기·서울 GPX 13개·4단계 절차가
한 제목 밑에 쌓여 있었다. 접는 것(`<details>`)으로는 계층이 늘지 않아서, 참고
자료와 가져갈 도구를 한 단계 아래로 내렸다. 홈에는 한 문장과 링크만 남는다.
문자열 키는 옮기기 전 그대로라 6개 사전에 새로 번역할 것이 없었다.

## 특징
- 실제 앱 UI를 재현한 SVG 목업 (심박존 아크·대시보드·GPS 지도)
- **5km 스크롤 데모**(`run.html`): 스크롤이 곧 러닝. 코치가 언제·왜 개입하는지 큐 단위로
- **음성 코칭 체험**: Web Speech API로 실제 코치 멘트 재생 — 표시 언어를 따라 6개 언어
- 다크 프리미엄 톤 · 반응형 · prefers-reduced-motion 대응
- 개인정보보호법 준수 베타 신청 폼(수집목적·보관기간·마케팅동의 분리)

## 언어 라우팅 — 무엇이 렌더를 정하고, 무엇이 제안만 하는가

**루트는 한국어 문서다.** `hreflang="ko"`가 `/`를 지목하고, `sitemap.xml`이 `/`를
한국어 URL로 올리고, canonical이 `/`다. 그러니 `/`를 렌더한 결과는 한국어여야
한다 — 브라우저 언어가 무엇이든, **크롤러를 포함해서**.

라운드 13까지의 부트 스크립트는 그 반대였다. 루트에서 `?lang=`도 저장된 선택도
없고 `navigator.language`가 한국어가 아니면 `location.replace("/"+code+"/")`를 했다.
구글봇은 JS를 실행하고 `navigator.language`가 `en-US`이며 스토리지가 비어 있다 —
즉 정확히 그 조건이다. 그래서 `hreflang="ko"`로 자기를 한국어 정본이라고 선언한
문서가, 그 선언을 읽으러 온 크롤러를 `/en/`으로 밀어냈다(라운드 14 −4).
겪는 것과 선언한 것이 정면으로 어긋나면 한국어 페이지는 색인에서 자기를 지운다.

지금 규칙은 세 줄이다.

1. **렌더를 정하는 것**: `?lang=` → 이 문서가 놓인 디렉터리(`RunvisPageLang`) →
   저장된 선택 → **이 문서 자신의 언어**. `navigator.language`는 여기 없다.
2. **아직 남아 있는 유일한 자동 이동**: 루트에서, 저장된 선택이 있을 때만
   `/<code>/`로 `replace`한다. 저장은 URL이 언어를 **이름으로 부른** 경우에만
   일어난다(`?lang=`, 또는 `/de/` 같은 디렉터리 — `i18n.js`의 `applyLang(code,
   remember)`). 헤더는 저장을 만들지 못하고, 크롤러는 스토리지가 비어 있으므로
   이 분기에 절대 닿지 않는다. 라운드 9의 '다섯 페이지가 있는데 아무도 안
   보내진다'로 되돌아가지 않는 장치가 이것이다.
3. **`navigator.language`가 하는 일**: 배너 하나. 표시 중인 언어와 다르면
   `i18n.js`가 페이지 맨 위에 "이 페이지는 …로도 볼 수 있습니다 + 링크"를 붙인다.
   목적지는 **그 문서의 `<link rel="alternate" hreflang>`에서 읽는다** — 경로를
   조립하지 않으므로 배너가 hreflang 클러스터와 어긋날 수가 없다. 서버 리다이렉트가
   불가능한 사이트(GitHub Pages)에 구글이 문서로 권하는 형태이기도 하다.
   `404.html`만 예외로 `navigator.language`가 렌더를 정한다 — noindex이고
   canonical도 hreflang도 sitemap 항목도 없어서, 어긋날 선언이 없다.

canonical은 **화면에 보이는 언어**를 따른다(이 문서 자신의 언어와 다르면
`/<code>/`). `?lang=de`만 그랬고 저장된 선택은 빠져 있어서, 영어 본문이 canonical
`/` 아래에 놓이던 자리를 라운드 14에 함께 막았다(−1.5).

이 전부를 `check-content.mjs` 20번이 **실행해서** 확인한다. 주석이 코드보다 앞선
전례가 있는 자리라, 문장이 아니라 동작을 본다.

## 빌드 (커밋 전에 반드시)
사이트에 빌드 산출물이 있다. `en/ ja/ es/ zh/ de/` 25개 파일은 **손으로 고치지 말 것** —
루트 페이지(`index.html`·`run.html`·`how-it-works.html`·`privacy.html`·`terms.html`)나
사전(`t-<code>.js`)을 고친 뒤 아래 두 명령을 순서대로 돌린다.

```
node tools/prerender.mjs      # /en /ja /es /zh /de 재생성 (5페이지 × 5언어) + sitemap.xml
node tools/check-content.mjs  # 드리프트 검사 — 실패하면 커밋하지 말 것
```

에셋을 건드렸을 때만 그 앞에 두 개가 더 붙는다. 둘 다 산출물이 저장소에 커밋돼
있으므로 평소에는 돌릴 일이 없고, `--check`가 빠진 것을 알려준다.

```
python3 tools/encode_shots.py  # framed-*.png 옆에 .avif/.webp (캡처를 다시 찍었을 때)
python3 tools/og_cards.py      # 6개 시장 공유 카드 (n.hero.h1 을 고쳤을 때)
```

페이지를 하나 더 만들 때 손대야 하는 곳은 네 군데다 —
`tools/i18n-lib.mjs`의 `PAGES`와 `PAGE_META`, `i18n.js`의 `PAGE_META`
(?lang= 로 언어를 바꿀 때 JSON-LD를 다시 쓰는 런타임 사본), 그리고 그 페이지의
`<head>`에 hreflang 7줄. 나머지(프리렌더 사본·sitemap·검사)는 따라온다.

앱 저장소가 움직였을 때(테스트·문자열 개수가 바뀌었을 때)는 그 앞에 한 번 더:

```
node tools/app-facts.mjs      # 앱 리포에서 숫자를 다시 세어 tools/app-facts.json 갱신
```

`check-content.mjs`가 잡는 것:
0. `tools/app-facts.json`이 **지금** 앱 저장소를 센 값인가. 9번은 사전과 이 파일만
   비교하므로, 파일이 뒤처지면 사전은 통과하는데 '앱 저장소에서 그대로 세어 나온
   숫자'라는 문구가 거짓이 된다(라운드 12 감점). 앱 체크아웃이 없는 머신에서는
   `skip`을 **소리 내어** 출력한다 — 조용한 통과와 구분하기 위해서다
1. 6개 사전의 키 집합이 같은가
2. 마크업이 쓰는 `data-i18n` 키가 6개 사전에 전부 있는가
3. 각 페이지의 **인라인 기본 텍스트**가 그 페이지 언어의 사전 값과 같은가
   (크롤러와 JS 없는 방문자가 보는 것은 인라인 기본값뿐이다)
4. 정적 JSON-LD가 사전과 **문자 단위로** 같은가 — index의 FAQPage·SoftwareApplication,
   그리고 run/privacy/terms의 WebPage + BreadcrumbList
   — 라운드 7에서 8문항 중 3문항이 화면과 어긋난 채 검색에 나가던 사고가 이 검사로 막힌다
5. 프리렌더 산출물이 최신인가 (루트만 고치고 재생성을 잊는 사고 방지)
6. hreflang 7줄이 전부 있고 각 대상 파일이 실재하는가
7. index의 섹션 9개 · 태그 균형
8. (7과 같은 블록) 30개 페이지 + `404.html` 전부 태그 균형
9. 신뢰 블록이 인용하는 앱 숫자(테스트 · 번역표 · 지표 설명)가
   `tools/app-facts.json`과 같은가 — 숫자 자체는 이 문서에도 마크업 주석에도
   적지 않는다. 유일한 출처는 `node tools/app-facts.mjs`가 쓰는 그 JSON이다.
   화면 문구 개수와 큐 개수는 **하한 표기**라
   (`2,100개 이상` / `270개 이상`) 저장소 값이 그 아래로 내려갈 때만 실패한다 —
   502↔506, 2,077↔2,118, 2,118↔2,162가 네 라운드 연속으로 어긋난 자리이고,
   앱이 문자열을 더할 때마다 여섯 사전이 함께 낡는 구조 자체를 없앴다
10. 페이지 스크립트의 `RunvisT(키, 인라인 폴백)` 폴백이 그 페이지 언어의 사전 값과 같은가
11. `sitemap.xml`이 실제 존재하는 30개 페이지와 정확히 일치하고 `robots.txt`가 그것을 가리키는가
12. **조건이 붙은 주장**이 6개 언어에서 그대로 살아 있는가. 사전과 마크업이 일치해도
    문장을 다시 쓰다가 조건만 빠지면 이 검사만 잡는다 —
    `n.faq.a1`은 아이폰 심박존 큐가 블루투스 심박 밴드를 요구한다는 조건을 반드시 담고
    (`PhoneWorkoutManager`의 심박원은 `HeartRateBandManager`(BLE 0x180D) 하나뿐이고
    `PhoneCoachPlan.zoneCue`는 심박 0이면 nil을 돌려준다),
    `r20`은 코치가 실제로 말하지 않는 '2.5km'를 어느 언어에서도 담지 않는다
13. **앱 상수를 산문으로 옮겨 적은 자리**가 아직 앱과 같은 숫자인가.
    큐 토글 개수·30분 예산(8/6)·최소 간격(45초)은 `CoachSessionProfile.swift`의
    리터럴이고 `app-facts.mjs`가 그것을 세어 둔다. 앱은 라운드 7에 페이월 문구를
    `String(format:)` 인자로 바꿔 이 사고를 없앴는데 웹은 6개 언어 문장이라
    그럴 수 없어서, 대신 이 검사로 묶었다. 그래서 여섯 언어 모두 이 숫자들을
    **아라비아 숫자로** 쓴다("eight cues"였으면 검사가 못 본다)
14. 세 가격(₩1,900 · ₩15,000 · ₩39,000)이 6개 사전에서 같은가.
    값 자체(`pr.month`/`pr.year`/`pr.life`)와, 그 값을 문장 안에 인용하는
    `n.why.cost`·`n.price.year`·`n.price.life`까지 본다.
    반대 방향 불변식이 하나 있다 — `n.hero.note`에는 **원화 금액이 없어야** 한다.
    히어로가 여섯 시장 모두에게 ₩1,900을 보여주는데 다섯 시장은 그게 큰 값인지
    작은 값인지 알 길이 없었고(라운드 13 −0.8), 환산액을 적는 것도 답이 아니다
    — 애플은 환율이 아니라 가격대로 청구하고(`pr.approx2`가 그렇게 적는다),
    손으로 적은 숫자는 결제하는 날 틀린다. 금액은 어느 스토어 가격인지 적힌
    가격표 옆에만 산다
15. 유료 타일 7개의 이름이 **앱이 부르는 그 이름**인가. 이름은 앱의 여섯
    `Localizable.strings`에서 `app-facts.mjs`가 읽어 `tiles`에 넣는다.
    사이트는 가격 목록(`n.price.t1~t7`)·문턱 목록(`n.price.g1~g7`)·스크린샷
    대체텍스트(`alt.phone.glance`)·비교표(`hw.vs.r3a`) 네 곳에서 이 이름을
    되풀이하는데, 대조하는 것이 없어서 네 가지가 어긋나 있었다 — 라운드 4에
    폐기된 '언덕 점수'가 대체텍스트에 아홉 라운드를 살아남았고, 가격 목록에는
    앱이 쓰지 않는 坂の露出 / 坡道暴露 / Bergexposition이 들어 있었다.
    대소문자는 무시한다(스페인어·독일어는 문장 첫머리와 문장 안의 표기가 다르다)
16. `t-zh.js`가 **한자와 한자 사이에 공백을 두지 않는가**. 숫자·라틴문자와 한자
    사이의 공백은 중문 조판 관례라 그대로 두고, 한자 사이만 잡는다. 히어로 음성
    칩 문장과 서울 코스 이름 8개를 포함해 12개 값이 한국어 띄어쓰기를 그대로
    옮겨 온 상태였다(라운드 13 −0.5)
17. 모든 문서가 `apple-touch-icon`과 `manifest`를 걸고 있고, 그것들이 가리키는
    파일이 실재하는가. 없는 아이콘을 가리키는 `<link>`는 아이콘이 없는 것보다
    나쁘다 — iOS가 스크린샷 폴백을 멈추고 빈 타일을 저장한다
18. **무료 기간을 말하는 네 문장**(`pl.ribbon`·`n.price.sub`·`n.price.year`·`n.faq.a7`)이
    `Runvis.storekit`의 `introductoryOffer.subscriptionPeriod`와 같은 길이를
    말하는가. 여섯 언어 모두 "첫 기간"이라고만 적어서, 연간의 무료 구간이 1년으로
    읽혔다 — 실제 값은 월간과 같은 P1M이다(라운드 14 −2.5). 숫자는
    `app-facts.mjs`가 `.storekit`에서 읽어 `trialMonths`에 넣고, 검사는 각
    언어의 '개월/month/か月/mes/個月/Monat'과 붙은 자릿수를 본다 — 그래서 모호한
    표현으로 되돌아가면 통과하지 못한다
19. **5km 데모의 폼 대사 수치가 앱의 판정을 통과하는가**. `r37`이 인용하는 두
    퍼센트를 `FormDrift.evaluate`의 산식에 넣어 실제로 경고가 나오는지 계산하고,
    여섯 사전이 그 두 숫자를 인용하는지 본다. 예전 값 5%/7%는 평균 6.0에 신호 0이라
    앱이 절대 말하지 않는 조합이었다(라운드 14 −1). 임계값은 `app-facts.mjs`가
    `FormDrift.swift`에서 읽는다
20. **크롤러가 렌더한 결과가 그 문서의 선언과 같은가**. 각 페이지의 `<head>` 부트
    스크립트를 파일에서 잘라내 실제로 실행한다 — 영어 헤더에 스토리지 없음, 즉
    구글봇의 조건 — 그리고 (a) 아무 데로도 이동하지 않았는지 (b) `<html lang>`이
    선언과 같은지 (c) canonical·og:url이 `sitemap.xml`의 그 페이지 URL과 같은지를
    본다. 독일어 브라우저로 루트를 렌더한 경우와, 저장된 선택이 있는 방문자가
    아직 자기 시장 페이지로 보내지는지도 함께 본다. 라운드 12·13이 "고쳤다"는
    주석을 코드보다 먼저 단 자리라, 이 검사만은 주석이 아니라 실행을 본다
21. **마크업과 JSON-LD가 가리키는 이미지가 전부 실재하는가**. 캡처가 `<picture>`가
    되면서 캡처 한 장이 파일 세 개(PNG·AVIF·WebP)가 됐고, 그중 둘은 `<source
    srcset>`이 가리킨다 — 그리고 `<source>`는 404를 만나도 다음 후보로 내려가지
    않고 그냥 아무것도 그리지 않는다. 조용히 실패하는 참조라서 디스크와 대조한다

- **캡처 한 장은 파일 세 개**: `framed-*.png` 옆에 `.avif`(q62, 원본의 50%)와
  `.webp`(무손실, 86%)가 있고, 마크업은 `<picture>`로 셋을 순서대로 제시한다.
  `python3 tools/encode_shots.py`가 만든다. WebP를 **무손실**로 쓰는 것은 품질
  판단이 아니라 크기 판단이다 — 원본이 이미 팔레트(PNG8)라 손실 WebP는 글자가
  살아 있는 어떤 품질에서도 PNG보다 커졌다(q88에서 104%). 되돌아가려는 다음
  사람을 위해 숫자를 `tools/encode_shots.py` 주석에 적어 뒀다.
  LCP 프리로드는 AVIF를 `type=image/avif`로 건다 — AVIF를 못 읽는 브라우저는
  링크 자체를 건너뛰고 `<picture>`에서 WebP/PNG를 받는다. 세 개를 다 프리로드하면
  세 개를 다 받는다.
